# Bruno-Collection (abgeleitet aus `httpRequests/`)

Die IntelliJ-HTTP-Requests unter `httpRequests/` bleiben der Master (Source of Truth). Diese
Bruno-Collection wird daraus als **OpenCollection YAML** generiert und dient als Alternative zum
IntelliJ HTTP Client sowie zur Automatisierung per CLI.

Aktueller Stand: REST-Flow (`restRequest/country-flow`) und SOAP-Flow
(`soapRequest/country-versions-flow`). SOAP-Bodies werden beim Generieren aus den externen
XML-Dateien (`< ../getCountryRequest*.xml`) **inline** in die Bruno-Requests übernommen, weil
Bruno keine Datei-Referenzen im Body kennt.

## Struktur

```text
httpRequests/bruno/
├── opencollection.yml          # Collection-Root (YAML)
├── environments/
│   ├── local.yml               # application-port 8080
│   └── k8s.yml                 # application-port 30080
├── restRequest/
│   └── country-flow/           # 6 Schritte aus country-flow.http
├── soapRequest/
│   └── country-versions-flow/  # 8 Schritte aus country-versions-flow.http
├── wsdl/                       # Contract-Snapshots V1/V2/V3 + generierte Requests
└── tools/
    ├── http-to-bru.mjs         # Generator .http -> .yml
    ├── import-wsdl.mjs         # bru import wsdl + URL/xmlns-Fix
    ├── package.json            # @usebruno/filestore
    └── package-lock.json
```

Jeder `.http`-Block wird zu einer `.yml`-Datei; Ordner und Reihenfolge (`seq`) entsprechen dem
Master. Flow-Dateien landen im gleichnamigen Ordner. `< datei.xml` im Body wird als
Datei-Include erkannt und der Inhalt beim Generieren inline eingebettet; `< script.js` bleibt ein
Script-Include.

## Generieren

```bash
cd httpRequests/bruno
npm ci --prefix tools
node tools/http-to-bru.mjs --source ../restRequest/country-flow
node tools/http-to-bru.mjs --source ../restRequest/country-flow --check   # nur prüfen
```

Der Generator überschreibt nur Dateien mit dem Marker `Generated by tools/http-to-bru.mjs` und
entfernt veraltete generierte Dateien im Zielbereich. Die `.http`-Dateien werden nicht verändert.

## Ausführen

```bash
cd httpRequests/bruno

# gesamter REST-Flow
bru run restRequest/country-flow --env local

# k8s-Profil (NodePort 30080)
bru run restRequest/country-flow --env k8s
```

Runtime-Variablen (`bru.setVar`) überleben nur einen CLI-Lauf: Schritt 5 (`httpexchanges`) kann
nicht allein gestartet werden, sondern nur im Flow-Verbund.

## Script-Übersetzung

Der Generator mappt die IntelliJ-Scripting-API auf Bruno:

|          IntelliJ          |             Bruno             |
|----------------------------|-------------------------------|
| `client.global.set/get`    | `bru.setVar/getVar`           |
| `client.test`              | `test`                        |
| `client.assert(cond,msg)`  | `expect(cond,msg).to.be.true` |
| `response.status`          | `res.status`                  |
| `response.body`            | `res.body`                    |
| `response.headers.valueOf` | `res.getHeader`               |
| `client.log`               | `console.log`                 |

Verschachtelte Objekte wie `exchange.response.status` werden bewusst **nicht** ersetzt
(Lookbehind im Generator), da sie normale JS-Objekte aus dem Response-Body sind.

## WSDL-Contract

Die generierten WSDLs (V1/V2/V3) und die daraus per `bru import wsdl` erzeugten Requests liegen
unter `wsdl/` (Wrapper: `tools/import-wsdl.mjs`, korrigiert URL und Target-Namespace). Diese
Requests sind nur ein Gerüst (Beispiel-Body, keine Trace-Header, nur 200-Check); der Master
für Flows bleibt die `.http`-Ableitung. Details: `wsdl/README.md`.
